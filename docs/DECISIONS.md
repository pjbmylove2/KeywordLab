# 결정 사항

작업 전에 이 문서를 읽는다. 여기 적힌 결정을 바꿔야 하면 코드보다 이 문서를 먼저 고친다.

## 범위

- 핫한 키워드·검색량·최근 트렌드를 보고 **주제와 추천 제목을 정하는 곳까지**가 이 앱의 범위다.
- 본문은 Codex의 마스터 프롬프트(네이버 v1.0, 티스토리 v2.3)가 작성한다.

## 환경

- Visual Studio 2022, .NET 8, 로컬 전용.
- 공개 저장소다.

## 제목 생성

- LLM API 키 없이 만든다. 제목은 **템플릿 조합 + 규칙 점수**로 만든다.
- 나중에 LLM을 붙일 수 있게 제목 생성기는 **교체 가능한 인터페이스**로 둔다.
- 제목 패턴: **정보 정리형, 질문형, 시점형**.
- 메인 키워드는 **원형 그대로 제목 앞쪽**에 둔다.
- 검색 의도 키워드(자동완성·연관키워드)는 **1~2개**만 넣는다.

### 플랫폼별 점수

| 플랫폼 | 가점 | 감점 |
|---|---|---|
| 티스토리 | 40자 이내, 연도·월 표기 | |
| 네이버 | (길이 제한 없음) | 같은 단어 반복, 과장 표현, 특수문자 남용 |

- 금지 표현(충격, 경악, 모르면 손해, 무조건, 역대급 등)은 **설정값**으로 둔다 (코드에 고정하지 않는다).

## Codex로 넘기기

- **추천 제목 1개 + 대안 제목 2개**를 넘긴다.
- 제목은 고정이 아니다. Codex는 조사 결과가 사실과 맞지 않으면 **핵심 키워드를 유지한 채** 제목을 고친다.

### 입력 블록 형식

```
[키워드 데이터 - {날짜} 네이버 검색광고 API 확인]
플랫폼:
주제:
핵심 키워드: {키워드} (월간 검색량 {n}, 블로그 문서 수 {n})
관련 키워드:
추천 제목:
대안 제목:
이슈 배경(참고용, 검증 전):

[적용 규칙]
- 핵심 키워드를 1단계 핵심 키워드로 사용
- 검색량은 확인된 데이터로 취급하되 본문에 수치 노출 금지
- 추천 제목 우선, 사실과 다르면 키워드 유지한 채 수정하고 이유 명시
- 이슈 배경 뉴스는 2단계에서 검증
```

### 기록

- 블록을 복사할 때 **키워드·플랫폼·제목·패턴·시각**을 자동 저장한다.
- 별도 기록 화면은 만들지 않는다.

## 카테고리

- 블로그별로 **허용 카테고리**를 둔다.
- 네이버는 C-Rank 주제 일관성 때문에 좁게 잡는다.
- 카테고리 밖 키워드는 목록에서 **흐리게 표시**한다 (숨기지 않는다).

## 자동 모드 키워드 점수

```
점수 = 수요 × 경과 시간 가중치 × 문서 수 보정
```

- 수요: 신규 키워드는 **구글 트렌드 예상 트래픽**, 며칠 지난 키워드는 **네이버 월검색**을 쓴다.
- 경과 시간 가중치: 키워드가 등장한 뒤 지난 시간에 따른 가중치.
- 문서 수 보정: 검색량 대비 블로그 문서 수로 보정한다.

## 구글 트렌드 RSS

- 주소: `https://trends.google.co.kr/trending/rss?geo=KR`
- 언어 파라미터(`hl` 등) 조합에 따라 빈 응답이 올 수 있다. **수집기 첫 작업에서 실제 응답을 확인**하고 쓸 조합을 이 문서에 적는다. (미확인)
