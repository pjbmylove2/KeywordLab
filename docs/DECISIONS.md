# 결정 사항

작업 전에 이 문서를 읽는다. 여기 적힌 결정을 바꿔야 하면 코드보다 이 문서를 먼저 고친다.

## 범위

- 핫한 키워드·검색량·최근 트렌드를 보고 **주제와 추천 제목을 정하는 곳까지**가 이 앱의 범위다.
- 본문은 Codex의 마스터 프롬프트(네이버 v1.0, 티스토리 v2.3)가 작성한다.

## 환경

- Visual Studio 2022, .NET 8, 로컬 전용.
- 공개 저장소다.

## 제목 생성

- LLM API 키 없이 만든다. 제목은 **템플릿 조합 + 규칙 점수**로 만든다.
- 나중에 LLM을 붙일 수 있게 제목 생성기는 **교체 가능한 인터페이스**로 둔다.
- 제목 패턴: **정보 정리형, 질문형, 시점형**.
- 메인 키워드는 **원형 그대로 제목 앞쪽**에 둔다.
- 검색 의도 키워드(자동완성·연관키워드)는 **1~2개**만 넣는다.

### 플랫폼별 점수

| 플랫폼 | 가점 | 감점 |
|---|---|---|
| 티스토리 | 40자 이내, 연도·월 표기 | |
| 네이버 | (길이 제한 없음) | 같은 단어 반복, 과장 표현, 특수문자 남용 |

- 금지 표현(충격, 경악, 모르면 손해, 무조건, 역대급 등)은 **설정값**으로 둔다 (코드에 고정하지 않는다).

## Codex로 넘기기

- **추천 제목 1개 + 대안 제목 2개**를 넘긴다.
- 제목은 고정이 아니다. Codex는 조사 결과가 사실과 맞지 않으면 **핵심 키워드를 유지한 채** 제목을 고친다.

### 입력 블록 형식

```
[키워드 데이터 - {날짜} 네이버 검색광고 API 확인]
플랫폼:
주제:
핵심 키워드: {키워드} (월간 검색량 {n}, 블로그 문서 수 {n})
관련 키워드:
추천 제목:
대안 제목:
이슈 배경(참고용, 검증 전):

[적용 규칙]
- 핵심 키워드를 1단계 핵심 키워드로 사용
- 검색량은 확인된 데이터로 취급하되 본문에 수치 노출 금지
- 추천 제목 우선, 사실과 다르면 키워드 유지한 채 수정하고 이유 명시
- 이슈 배경 뉴스는 2단계에서 검증
```

### 기록

- 블록을 복사할 때 **키워드·플랫폼·제목·패턴·시각**을 자동 저장한다.
- 별도 기록 화면은 만들지 않는다.

## 카테고리

- 블로그별로 **허용 카테고리**를 둔다.
- 네이버는 C-Rank 주제 일관성 때문에 좁게 잡는다.
- 카테고리 밖 키워드는 목록에서 **흐리게 표시**한다 (숨기지 않는다).
- 판별은 LLM 없이 **카테고리별 단어 목록**으로 한다. 키워드·자동완성어·관련 뉴스 제목에 목록의 단어가 들어 있으면 그 카테고리로 본다.
  어느 목록에도 안 걸리면 카테고리 밖으로 본다.

## 자동완성

- **네이버 자동완성**(`ac.search.naver.com`)을 쓴다. 띄어쓰기가 살아 있어 의도 키워드를 뽑기 쉽다.
- 공식 API가 아니라서 예고 없이 막힐 수 있다. 실패하면 오류로 멈추지 않고 자동완성 없이(연관 키워드만으로) 동작한다.

## 3단계 나누기

- 3-1: 수집기(구글 트렌드 RSS·네이버 자동완성) + 키워드 점수 + 오늘의 이슈 키워드 화면. 카테고리는 appsettings.json 임시값.
- 3-2: 설정 화면 (블로그별 허용 카테고리, 금지 표현 편집).

## 자동 모드 키워드 점수

```
점수 = 수요 × 경과 시간 가중치 × 문서 수 보정
```

- 수요: 신규 키워드는 **구글 트렌드 예상 트래픽**, 며칠 지난 키워드는 **네이버 월검색**을 쓴다.
- 경과 시간 가중치: 키워드가 등장한 뒤 지난 시간에 따른 가중치.
- 문서 수 보정: 검색량 대비 블로그 문서 수로 보정한다.
- 3-1 처음 값 (appsettings.json "IssueScoring", 써 보면서 조정):
  - 신규 기준 48시간. 그 안이면 구글 예상 트래픽, 지나면 네이버 월검색 ÷ 30 (하루 기준으로 단위 맞춤).
  - 경과 시간 가중치 = 0.5 ^ (경과 시간 ÷ 24시간).
  - 문서 수 보정 = 1 ÷ (1 + (블로그 문서 수 ÷ 기준 검색량) ^ 세기). 세기(`DocPenaltyExponent`)는 1.
    - 기준 검색량: 신규 키워드는 네이버 월검색과 구글 트래픽 × 30 중 큰 쪽 (월검색은 지난달 기준이라 막 뜬 수요를 못 따라감).
      신규가 지나면 네이버 월검색. 월검색이 없으면 구글 트래픽 × 30.
    - 2026-11-06 조정: 처음엔 신규 키워드도 네이버 월검색만 써서 과징금(구글 500+, 문서 35만, 월검색 1,730)이 2점이었다.
      기준 검색량을 바꿔 20점이 됐다. 세기 0.5도 비교했지만 문서 1,033만 건인 "죽음"이 2위로 올라와 1을 유지했다.
  - 최근 72시간 안에 등장한 키워드 중 임시 순위(구글 트래픽 × 시간 가중치) 상위 15개만 네이버를 조회한다.

## 구글 트렌드 RSS

- 주소: `https://trends.google.co.kr/trending/rss?geo=KR`
- 2026-11-06 확인: `?geo=KR`만 쓴다. `hl=ko`, `hl=ko-KR`, `hl=en-US`, `hours=24`를 붙여도, `trends.google.com` 호스트로 바꿔도 같은 결과(HTTP 200, 항목 10개)였고 빈 응답은 없었다.
- 항목마다 `title`(키워드), `ht:approx_traffic`(예상 트래픽, "200+" 형식), `pubDate`, `ht:news_item`(관련 뉴스 제목·URL·언론사)이 온다. 한 번에 10개뿐이므로 주기적으로 모아 쌓는다.
- 빈 응답이 다시 생기면 이 항목을 고친다.
